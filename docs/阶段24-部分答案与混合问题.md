# 阶段 24 · 部分答案与混合问题

> 依赖阶段 23（行情 MCP 接入）。本阶段是**修缺陷**性质的收尾，没有独立 ST 计划文档：
> 口径写在契约 **C41**，实测与偏差写在这里。

## 1. 做了什么

| # | 问题 | 修法 |
|---|---|---|
| 1 | `sufficient=false` 但答案非空时，引用与事实被整段清空 → 正文里的 `[E8]`/`[F900]` 变成点不开的死角标 | `AnswerService.evaluate` 只在「一个字都没有」时早退；答了一部分就走完整校验，保留 `citations`/`facts`，`confidence` 落 `insufficient` 并留痕 `partial_answer` |
| 2 | 混合问题（年报 + 行情）没有确定性时间戳，数字靠模型转述 | `RealAnalysisNodes.withMarketStamp` 在答案末尾补脚注；正文没提行情数字时把数字一并写全 |
| 3 | 行情 6 行事实被当成「兜底抽取」丢掉 | `AnswerService.mergeFacts` 给 `source=MARKET` 单独预算，顺序＝计算事实 → 行情事实 → 模型事实 |
| 4 | 行情行混在【已报事实】里，模型拿报告期否它 | `FactPack.from` 渲染第三段【实时行情】，写明「当前时点快照，与报告期无关」 |

## 2. 为什么必须做

2026-11-04 19:40 的实测（旧 jar，8081）：

```
问：东方财富2025年净利润和现在股价                → 20.4 s
sufficient=false  confidence=insufficient  citations=0  facts=[]
正文：…净利润 12,084,594,947.22 元 [E8]；当前股价（截至2026年11月4日）为19.20元 [F900]
```

正文写了两个角标，接口一条引用一条事实都没返回 —— 前端既点不开、也看不到事实卡。
这不是「答得不全」，而是**证据被删掉**：`sufficient` 是结论层面的标记，不该决定要不要交出证据（C7）。

第二次实测暴露第二层问题：模型这次干脆不写股价（只写「无法获取现在股价」），
而脚注当时只写时间不写数字 → 用户完全看不到行情；`facts` 里 6 条全是 PDF（行情行被兜底逻辑吞了）。

## 3. 关键实现

### 3.1 部分答案（`AnswerService.evaluate`）

```java
boolean partial = !dto.sufficient();      // 模型自己说不够
if (partial) warnings.add(WARNING_EVIDENCE_INSUFFICIENT);
if (answerText.isBlank()) { …早退给固定拒答文案… }   // 只有这一种才丢证据
…完整校验：引用 / 事实 / 数字回查 / 版式…
if (partial) {
    warnings.add(WARNING_PARTIAL_ANSWER);            // "partial_answer"
    return new AnswerResult(false, answerText, outFacts, citations.citations(),
            CONFIDENCE_INSUFFICIENT, note, warnings, citations.dropped().size());
}
```

### 3.2 行情脚注（`RealAnalysisNodes.withMarketStamp`）

条件：`MARKET_FACTS` 非空、`MARKET_AS_OF` 非空、答案里没有「数据时间」。

逐项去重（`marketLine(rows, answer)` 跳过正文已出现的 `value`/`display`，最多 4 项）：

| 正文情况 | 追加 |
|---|---|
| 行情数字一个都没写 | `> 实时行情：最新价 19.20 元，涨跌幅 1.80%，总市值 3037.88 亿元（数据时间：…，来源：…）` |
| 写了一部分（如只写市值） | 同上，但只含没写过的那几项 |
| 全写过了 | `> 行情数据时间：2026-11-04 15:34（北京时间），来源：东方财富公开行情。` |

### 3.3 提示词分段（`FactPack.from`）

```
【实时行情】（当前时点快照，与报告期无关；问题问「现在/目前/今天」时直接用这组数字，
不要说「年报里没有披露」；时间以〔〕里的数据时间为准）
[F900] 股价 = 19.20元〔实时行情 2026-11-04T15:34:06+08:00〕
```

## 4. 实测（2026-11-04 20:20，8081，新 jar）

| 问题 | 时延 | sufficient | citations | facts | 行情 |
|---|---|---|---|---|---|
| 东方财富2025年净利润和现在股价 | 15.7 s | **true** | 1 | **8（其中 6 条 source=MARKET）** | `get_quote` / asOf 2026-11-04T15:34:06+08:00 |
| 东方财富2025年营业总收入和现在市值分别是多少 | 23.2 s | true | 2 | 8（6 条 MARKET） | 同上；正文写了市值，脚注只补剩下 4 项 |
| 东方财富股价 | 4.5 s | true | 0 | 0 | `get_quote`，走 `answer_market` 模板 |
| 东方财富2025年净利润是多少 | 14.0 s | true | 1 | 6 | 不触发行情（trace.market 全空） |

混合问题（净利润 + 股价）的最终答案：

```
东方财富2025年归属于上市公司股东的净利润为12,084,594,947.22元（≈120.85亿元），
当前股价为19.20元 [E1]。

> 实时行情：涨跌幅 1.80%，总市值 3037.86 亿元，市盈率(TTM) 19.13 倍，市净率 2.97 倍
（数据时间：2026-11-04 15:34（北京时间），来源：东方财富公开行情）
```

「营收 + 市值」那题正文写了市值，脚注就跳过市值只补其余四项（逐项去重，最多 4 项）。

warnings：`["facts_table_skipped:32859","citation_dropped:1","answer_citations_dropped","market_live"]`
—— 模型多引了一个不存在的证据号，被引用校验摘掉（这是 C7 的正常行为，不是本阶段引入的）。

对比上一版（20:13，行情仍在【已报事实】段里）模型的原话：

> 该日期晚于 2025 年年报编制截止日（2025-12-31），不属于 2025 年财务报告期的「当前股价」信息，
> 故无法确定符合问题要求的「现在股价」。

分段之后同一问题变成直接给数——**一个提示词分段胜过一句「请忽略报告期」的叮嘱**。

## 6. 偏差登记

| # | 计划/预期 | 实际 | 原因 |
|---|---|---|---|
| D1 | 只改「部分答案别丢证据」 | 追加了混合问题脚注与 facts 预算两件事 | 冒烟发现行情数字在答案和事实卡里都消失，属同一用户可见缺陷 |
| D2 | 脚注固定为「行情数据时间：…」 | 正文没写行情就补全数字，写了就逐项去重、全写过才只补时间 | 模型经常完全不提行情，只补时间等于没答；而全量重复又会和正文冲突（「3037.86亿元」写两遍） |
| D3 | 行情行进【已报事实】段 | 改成第三段【实时行情】 | 混排时模型拿报告期否掉实时数据 |
| D4 | 「两个 ChatClient + checker=false」的执行策略改造 | **不做** | `toolcallback.enabled=false` 已保证没有任何 ChatClient 挂行情工具，改造纯防御、无行为变化，阶段 24 不做 |

## 7. 没做

- 混合问题的**对比式回答**（「2025 年净利润 120.85 亿 vs 当前市值 3037.86 亿 → PE 25.1」）——需要跨口径计算，留阶段 25。
- 行情落库/回放（C40.2 明确不做）。
- 指代消解（「那它现在多少钱」）——需要短期记忆改写，属 QU 多轮，留阶段 9 之后的增强。
- 纯行情问题（走 `answer_market`）仍不返回事实卡：数字都在正文、行情角标显示数据时间。要不要统一成事实卡留阶段 25 决定。
- 事实卡里「总市值」显示 `303786237600 元`（值精确到元，亿元换算只出现在脚注与正文）。要让卡片也显示亿元，得给 `Fact` 加 `display` 字段——留阶段 25。

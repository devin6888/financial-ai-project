# 阶段 6 · 冒烟评测报告

> 执行日期：2026-10-22。语料：东方财富 2024 年报（document_id=38，630 个 ACTIVE Child）+ 2025 年报（document_id=7，654 个 ACTIVE Child）。
> 评测集：`src/test/resources/eval/golden-set.json`，32 题。所有数字来自一次真模型、真数据库运行。

## 怎么读这份报告（先看这 8 个词）

| 词 | 一句话解释（完整版见 docs/术语表.md） |
| --- | --- |
| e2e（end-to-end，端到端测试） | 从真实输入一路跑到真实输出、中间不 mock 任何组件的测试。跑一次几十秒到几分钟、要调真模型花钱，所以默认不跑，用 `-Dgroups=e2e` 显式挑出来 |
| golden set（黄金集） | 人工标注的「问题 + 期望文档 + 期望数值 + 期望证据块」数据集，用来回归评测。本项目的 32 题就是它 |
| Recall@K（前 K 条召回率） | 前 K 条结果里至少含一条标注证据的题占比。本项目 @10 = 1.000 表示「27 道题的正确证据都进了前 10」 |
| MRR（Mean Reciprocal Rank，平均倒数排名） | 每题取「首个正确结果名次」的倒数（第 1 名 = 1、第 2 名 = 0.5、第 3 名 = 0.33）再平均。比 Recall 严格，会惩罚「排在第 5」 |
| 引用准确率 | 每条引用「文档对不对 + 块里是否真的有这个数」的比例。**光看数值准确率分不出「问 2024 答成 2025 年报的对比列」** |
| 消融（ablation） | 关掉某个模块看指标掉多少，以此证明它有用。本报告的消融对象是 QU（查询理解） |
| 门槛 / 闸门（gate） | 写死在代码里的指标下限（EvalGateTest），低于就不许合并 |
| 采样噪声 | 模型输出有随机性，同一题跑两次结果可能不同。所以「一次 1.000」不等于「永远 1.000」 |

## 1. 一句话结论

检索与答案的机器指标全部达标（Recall@10 = 1.000、引用准确率 = 1.000、数值准确率 = 1.000、拒答 5/5、期间标注 2/2），
但**评测真正的产出不是这组满分，而是它抓到的两个真 bug**：问「五粮液」时用东方财富的数字作答、以及模型编造了一个库里不存在的员工总数。
两个 bug 都已在本阶段修掉，并各自留下了回归测试。

## 2. 为什么阶段 5 的端到端测试（e2e）不够

阶段 5 的 `ChatE2ETest` 有 14 题、四条不变量（引用可反解析、引用不越界、数值逐字出现在被引块里、置信度合法），确实是绿的。
但它有三个结构性缺陷：

| 缺陷 | 后果 |
| --- | --- |
| 全部是「同年、同文档」的正例 | 只证明系统会答，不证明它**不答**不该答的 |
| 断言写在代码里 | 「哪些块算证据」是测试作者说了算，不是数据说了算 |
| 只跑一遍、看总数 | 没有基线，说不清「QU 到底有没有用」 |

阶段 6 的评测集把「证据」外置成数据（`evidenceChunkIds` 由 SQL 反查），把「该不该答」外置成题目类型（TRAP），并留了一条 NO-QU 对照道。

## 3. 评测集

| 类型 | 题数 | 说明 |
| --- | --- | --- |
| METRIC | 14 | 6 个指标 × 2 年 + 2 题「2023 年」（数值只存在于上年同期对比列） |
| NARRATIVE | 7 | 研发人员、前五名客户、关键审计事项、商誉、主营业务、应对措施、员工总数 |
| COMPARISON | 6 | 2024 vs 2025，作用域同时含两份报告 |
| TRAP | 5 | 2021 年、2019 年、碳排放、贵州茅台、五粮液 —— 全部超出语料 |

两条设计要点：

1. **evidenceChunkIds 不是手写的**，而是 `SELECT id FROM document_chunk WHERE content LIKE '%<期望值>%' AND status='ACTIVE' AND chunk_level='CHILD'` 反查出来的。手写必然漂移，反查保证「标注的证据块里真的有这个数」。
2. **对比列陷阱**：2024 的营业总收入同时出现在 2024 年报的「主要会计数据」表（1627）和 2025 年报的对比列（818）。所以判分必须同时看「块对不对」与「文档对不对」——只比值会全员满分。

Q31/Q32 是刻意加的「只有对比列才有」的题：它们是目前唯一能产生**期间标注样本**的题（引用文档年份 ≠ 问题年份）。

## 4. 指标与门槛

| 指标 | 口径 | 门槛 | 实测 |
| --- | --- | --- | --- |
| Recall@5 / @10 | top-K 至少含一条标注证据的题占比 | @10 ≥ 0.90 | **1.000 / 1.000** |
| DocRecall@10 | top-10 出现期望文档的题占比 | ≥ 0.90 | **1.000** |
| MRR | 首个证据名次倒数的平均 | 仅观测 | **0.779** |
| 引用准确率 | 每条引用「文档 ∈ 期望」且「块含期望数值」的比例，按题平均 | ≥ 0.90 | **1.000** |
| 数值准确率 | answer 或 facts 里出现全部期望数值的题占比 | ≥ 0.90 | **1.000** |
| 拒答正确率 | TRAP 题 `sufficient=false` 的比例 | = 1.00 | **1.000（5/5）** |
| 期间标注率 | 引用文档年份 ≠ 问题年份时带 `evidence_period_mismatch` 的比例 | = 1.00 | **1.000（2/2）** |

门槛写在 `EvalGateTest` 里，读的是评测落盘的 `target/eval-*.json`，不是重跑一遍——评测每次结果都不同，门槛必须落在同一份结果上。

## 5. 结果

### 5.1 检索：27 道可答题全中，但第一名常常不是答案块

| 模式 | cases | Recall@5 | Recall@10 | DocRecall@10 | MRR |
| --- | --- | --- | --- | --- | --- |
| 有 QU | 27 | 1.000 | 1.000 | 1.000 | 0.779 |
| 无 QU（基线） | 27 | 1.000 | 1.000 | 1.000 | 0.779 |

**两条道一模一样**，逐题名次也完全一致。原因不是 QU 没用，而是**这个语料上它没有发力的地方**：

- 作用域已经把文档锁到 1~2 份，QU 抽出的年份/公司过滤只会收窄到同一批块；
- 32 题里只有 3 题（Q03/Q08/Q19 一类）被 LLM 判为 EXACT_FACT，其余是 SEMANTIC_EXPLANATION 或 `DEGRADED:weak_evidence`——因为 `LlmRouter` 的系统提示要求「公司代码 + 年份 + 指标三要素齐全才判 EXACT_FACT」，而这些题都没写公司代码（作用域已经指定了）；
- 该判据是阶段 4 刻意设计的（§9.14：往误判代价更小的方向降级），不是缺陷。

MRR 0.779 的名次分布值得看：**17 题首个证据就是 top-1，6 题在第 2，1 题在第 3，3 题掉到第 4~5**。
掉队的 10 题是：Q02/Q08/Q12（指标）、Q15/Q16/Q30（叙述）、Q20/Q21/Q23（对比）、Q31（对比列）。
它们共同点是「问题问指标，检索先给回叙述段或表头段」。
这正是阶段 5 Context Building「Parent 内二次选择 + 邻居补齐」存在的理由：检索层只保证「话题找对了」，
上下文层才决定「哪一块真正进提示词」。

## 6. 四个发现

### 6.1 真 bug ①：问五粮液，答东方财富

第一次跑 Q29（「五粮液2024年营业收入是多少？」）时，系统给出：

> 五粮液2024年营业收入为 11,604,343,090.16 元……[E2][E4]

11,604,343,090.16 是**东方财富**2024 年的营业总收入。链条是这样断的：

1. `LlmRouter` 正确抽到 `companyIds=[000858]`；
2. `RouterService.validate` 里有一句 `filter(documents::companyExists)`，000858 不在 company 表里 → **静默丢弃**；
3. 于是检索只剩「2024 + 营业收入」两个约束，命中的是东方财富的对比列；
4. 答案生成、引用校验全部通过——引用是真的，只是主体的错的。

**修法**（两处）：`RouterService` 只校验代码格式、保留未知代码（`c.length()==6 && 全数字`）；`ChatService` 在检索前判断「QU 识别出的公司是否都在作用域内」，全都不在 → 直接拒答并记 `company_out_of_scope:CODE`，不检索、不调模型。

这类错误比乱答更危险：数值、页码、引用全部真实，只有主体是错的，人眼很难发现。

### 6.2 真 bug ②：模型编了 5,560 这个数

Q30 原本是一道陷阱题（「2024年员工总数是多少？」），第一次跑系统答：

> 2024年员工总数为 5,560 人，其中母公司在职员工 1,226 人，主要子公司在职员工 4,334 人。[E2]

扫库：document_chunk 里 **0 个块**含 `5,560` / `1,226` / `4,334`。三个数全是编的，引用编号却合法。
引用校验只看编号在不在本轮上下文里，管不了「数字是不是从证据里读出来的」。

**修法**：`AnswerService` 增加第四层校验 `ground()`——拿答案里的「报告式数字」（带千分位或四位以上）回查被引块正文，全部落空则**拒答**；单条 fact 的数字落空则丢弃该 fact 并记 `fact_value_not_in_evidence:指标`；部分落空降 `low`。模型自己算的百分比、增长率（如 38.4%）不在此列。

修完重跑，Q30 仍是 `high`、引用仍指向同一块——但这次是因为**它真的答对了**（见 6.3）。

### 6.3 同一个发现的两面：2025 年报的员工表被解析坏了

Q30 让我去查「为什么库里没有 5,560」，结果是两份报告解析质量不一样：

| 文档 | 块 | 内容 |
| --- | --- | --- |
| 2024 年报（38） | 1758 | `报告期末在职员工的数量合计（人） \| 5,560`，数字齐全 |
| 2025 年报（7） | 946 | 同一张表，只剩重复三次的表头，`产品与技术 \| 2,758` 之后就没有数字了 |

也就是说：**同一版式的表，2024 年报解析对了，2025 年报丢了数值列**（且表头被重复渲染三次）。这是阶段 2 解析层的遗留缺陷，不是检索或答案的问题，已记入未决问题。

顺带说明为什么它一开始看起来像「模型幻觉」：模型确实编了数（第一次跑时库里的确没有），但它编的恰好是正确答案——这种「编对了」最难分辨，也正是为什么必须做数字落地校验。

### 6.4 QU 在这个语料上没有增益，但有代价

- 增益：0（两条道指标完全相同）；
- 代价：每题多 1 次 LLM 调用（约 2.5~3 s）+ (1/5) 概率进入 `DEGRADED:weak_evidence` 重试，Q01 因此达到 11.6 s。

阶段 4 引入 QU 的动机是「Sparse 路不可用」（无实体时只能走 FTS 的 AND/OR 回退）。在这个语料上，Sparse 本来就不是主力（向量召回 30 条里已经覆盖证据），所以 QU 的价值要等**跨文档、跨公司、无作用域约束**的场景才体现。这也给阶段 7/8 一个明确判断依据：**如果作用域总是被 UI 锁死，QU 可以延后到多轮对话时再做**。

## 7. 这份满分的可信度

必须说清楚三件事，否则 1.000 会被误读成「系统没问题」：

1. **单次采样**：32 题各跑 1 次，温度已固定但 LLM 仍有抖动；重跑分数会变（尤其 `citationAccuracy`）。
2. **评测集是我为这个语料造的**：只有 2 份报告、2 个年份、1 家公司。跨公司（茅台/五粮液）、跨行业、长尾指标全部不在覆盖内。
3. **满分主要来自「检索容易」**：作用域锁定 1~2 份文档时，654~1,284 条的候选集对向量检索来说太简单了。真正难的是「不给作用域、10 万 chunk 里找一行」，那是阶段 8 之后的事。

期间标注只有 2 个样本（Q31/Q32），1.000 的置信区间几乎覆盖 [0,1]，只能当「机制通不通」的证据，不能当质量证明。

## 9. 复现

```powershell
. .\scripts\load-env.ps1

# 1) 评测集自检（不需要模型）
mvn -B test "-Dtest=GoldenSetTest" "-Dsurefire.excludedGroups=" "-Dgroups=e2e"

# 2) 检索评测（27 题 × 2 道，约 3 分钟）
mvn -B test "-Dtest=RetrievalEvalTest" "-Dsurefire.excludedGroups=" "-Dgroups=e2e"

# 3) 端到端评测（32 题，约 4 分钟；中途被杀可加 -Deval.resume=true 续跑）
mvn -B test "-Dtest=AnswerEvalTest" "-Dsurefire.excludedGroups=" "-Dgroups=e2e" "-Deval.resume=true"

# 4) 门槛（必须最后跑：它读 2、3 的落盘结果）
mvn -B test "-Dtest=EvalGateTest" "-Dsurefire.excludedGroups=" "-Dgroups=e2e"
```

`EvalGateTest` 与两个评测类是**顺序依赖**的（它读文件，不重跑）。按文件名排序 `EvalGateTest` 会先执行，
所以不能把三者放在同一条 `-Dtest=` 里——这条约束已写进 ST6 偏差登记。

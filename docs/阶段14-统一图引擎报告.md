## 怎么读这份报告（先看这 8 个词）

| 词 | 一句话解释（完整版见 `docs/术语表.md`） |
| --- | --- |
| 图（graph） | 把「理解 → 计划 → 检索 → 核对 → 生成」写成节点，节点之间用条件边连起来，可以回退、可以停 |
| 检查点（checkpoint） | 每跑完一个节点把状态存一行到 PostgreSQL，进程挂了能接着跑 |
| 人批（HITL） | 图停在某个节点前等人点「确认 / 修改 / 驳回」，本项目只给「问题有歧义」时用 |
| 旁路（bridge） | 不进图状态的东西（答案结果、trace）按 runId 存在内存里，一次请求一份 |
| 直链 | 阶段 5~13 的那条 `ChatService` 直线；阶段 14 已删除 |
| 运行视图（RunView） | 一次图运行的可观测快照：状态 / 计划 / 证据 / 步骤 / 答案 |
| 歧义 | 作用域里有多家公司或多份年份，而问题里没说清，需要人确认一次 |
| 阶段事件（stage） | 后端「正在做什么」的即时通知，阶段 14 起 `phase` 直接是节点 id |

## 1. 一句话结论

问答从此只有一条执行路径：**`/api/chat` 与 `/api/chat/stream` 内部都跑 LangGraph 图**；直链 `ChatService` 与其 29 条用例被删除，后端全量 **610 通过 / 0 失败 / 1 跳过**，流式 e2e 首屏 **18 ms**、证据 **5.8 s**、首字 **6.6 s**、总 **12.0 s**，前端 24 个单测与构建全绿。

## 2. 为什么非做不可

阶段 11 把问答搬进图，但只做成**可选**的第二条链路。两条链路意味着两套兜底：

| 能力 | 直链有 | 图（P1 之前） |
| --- | --- | --- |
| 会话落库 / 上下文 / 记忆命令 / 摘要 | ✅ | ❌（图跑完不落库） |
| facts / citations / confidence | ✅ | ❌（前端从 evidence 硬拼引用） |
| trace 落盘 | ✅ | ❌ |
| 证据先行（meta） | ✅ | ❌ |
| 人批 / 回退 / 检查点 | ❌ | ✅ |

用户的原话是「正常用户使用的时候，肯定不会自己去判断当前问题是否需要深度检索」（m10187），以及「最终的目标是所有问答全都走 langgraph4j」（m10200）。

## 4. 契约 C18 摘要（四条最容易写错的）

1. **一轮只收尾一次**：所有路径跑完都过 `TurnRecorder.record`（消息 → 上下文 → 记忆命令 → 摘要）；节点内不写会话表。
2. **结果不进状态**：`AnswerResult` / `Citation` / `Fact` 不是 `Serializable`，进 `AnalysisState` 会在写检查点那一刻炸 —— 走 `AnswerStreamBridge` 旁路。
3. **空作用域仍是 409**：图内写成 `scope_empty` + `REJECTED`，同步接口必须翻回 HTTP 409。
4. **`final` 是运行视图**：标准 `ChatResponse` 嵌在 `response` 里；`stage.phase` 换成节点 id。

## 6. 抓到的六个问题

### 6.1 检查点写不下去：答案结果不是 `Serializable`

**现象**：复杂问题停审批那一刻，运行直接 FAILED。
**原因**：图的检查点用 JDK 序列化写 `LG4JCheckpoint.state_data`，而 `AnswerResult`/`Citation`/`Fact` 都是 record 且没实现 `Serializable`。
**修法**：结果走 `AnswerStreamBridge`（按 runId 的三张表：sinks / results / traces），不进状态。
**教训**：**状态里只放能被「存档—恢复」的东西**；一次请求内的临时产物放旁路。

### 6.2 空作用域的 409 丢了

**现象**：`RestAuthContractTest.outsiderGetsScopeEmptyNotLeakedData` 由 409 变 200。
**原因**：图把「一份文档都看不到」写成 `scope_empty` 警告 + REJECTED，HTTP 层只看到一次「跑完了」。
**修法**：`AgentStreamService.ask` 在合成响应前判 `isScopeEmpty` 并抛 `ScopeEmptyException`。
**教训**：**图内部用状态表达失败，边界层必须把状态翻回协议语义**（C11 fail loud）。

### 6.3 首屏 4.4 秒：第一个 stage 等节点跑完才发

**现象**：e2e 红在 `firstStageMs=4395 > 300`。
**原因**：阶段事件是在「节点完成后」发的，而第一个节点 `understand` 本身要调 QU。
**修法**：`startStream` 第一行预发 `stage(understand)`，`progress` 里跳过 understand 不重发。
**教训**：**首屏事件不能挂在「最慢的第一步完成」之后**。

### 6.4 `final` 载荷变了，前端读不到答案

**现象**：前端拿到 final 后气泡空白。
**原因**：P4 后 `final` 是运行视图，`answer` 在顶层，但标准 `ChatResponse`（含 citations/trace）在 `response` 里。
**修法**：`chat.ts` 的 `onFinal` 取 `payload.response ?? payload`，兼容旧后端。
**教训**：改协议要么加版本，要么**新老同吃**（这里选了后者）。

### 6.5 歧义判定只能放在图外

**原因**：`CompileConfig.interruptsBefore` 是编译期配置，图一旦编译好就不能临时加/去中断点。
**修法**：`AmbiguityDetector` 在 `startStream` 里先判，再决定 `hitl` 参数。
**教训**：**编译期的东西不要指望运行期改**。

### 6.6 测试数从 638 掉到 609 不是回归

**原因**：删了 `ChatServiceTest`（25）与 `ChatServiceStageTest`（4）。
**判断依据**：断言等价分布在 `AgentStreamServiceTest`（4）、`AgentStreamE2ETest`（5）、`AnalysisGraphTest`（14）。
**教训**：**删测试必须说明「谁接管了断言」**，否则看起来像偷偷降低标准（见 `docs/测试规范.md` §7）。

### 6.7 resume 还读着已废弃的开关（真链路才抓到）

**现象**：聊天流弹确认卡 → 点「通过」→ 500。
**原因**：P4 只删了 `create` 里的 `finagent.agent.enabled` 检查，`resume` 里还留着；所有单元测试都用 `enabled=true` 构造，整类用例碰不到。
**修法**：删检查 + 补 `AgentHitlDbTest.resumeWorksWhileSwitchIsOff`。
**教训**：**入口闸门常在多个入口各写一遍**，删的时候要搜全仓。

## 7. 已知限制

1. 同步接口 `/api/chat` 用 `hitl=false`：没有通道把审批交回去，歧义问题在同步接口里不拦（前端只用流式）。
2. `stage.phase` 从四个中文阶段名换成节点 id，C16 的「四阶段」表述被 C18 §18.4 取代。
3. 歧义判定看不懂昵称（「东财」）→ 会多弹一次确认。
4. 图仍是一次运行：多轮靠会话表 + 记忆装配，不做图内重入。
5. 检查点表 `LG4JThread`/`LG4JCheckpoint` 不受 RLS 保护（C17 §17.3），隔离靠 runId 不可猜 + 应用层归属校验。

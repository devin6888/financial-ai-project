## 1. 结果总览

| 指标 | 数值 |
|---|---|
| Parent | **104** |
| Child | **654** |
| 无向量的 Child | **0** |
| active_chunk_version | **2**（首次端到端是 1，修断言后重跑生成 2） |
| 版本行数分布 | v1: 758 行 SUPERSEDED / v2: 758 行 ACTIVE |
| 读产物（COS 2.5 MB） | 2.99 s |
| 切块（纯计算） | **0.26 s** |
| 向量化 + 入库 | 61.9 s（654 条 / 66 次请求） |

**切块只要 0.26 秒** —— 这就是「原始 block 已持久化」的价值：重切不需要 2 小时的 PDF 解析。

| 统计 | 值 |

| min | 3 |

## 3. 两个「没达标」的地方，以及为什么不该硬凑

### 3.1 5 个表格单行超过 700

最大 1610，是「承诺事项」表的一行。**表格的一行是不可拆的原子单位** ——
按列拆会彻底破坏表语义（表头和数据的对应关系断裂）。

TEXT / LIST **100% ≤ 700**，因为它们可以按句子切。

### 3.2 ≥150 只有 68.8%

原因不是算法，是语料：

- **401 个表格 Child**，其中 67% ≥150。小表格（如两行的明细表）**不能与正文合并**，否则语义混乱。
- TEXT 里有大量 **3~7 token 的独立片段**：「不适用」「单位：元」「□是 否」——
  它们在年报里各自成行，且各自有章节路径。

**结论：§8.2 的「300~700 tokens」是期望值，不是这个语料的可达约束。**

## 4. 改用「上下文完整性」作为质量门

比 token 数更能衡量检索质量的是：**这个片段有没有携带足够的上下文**。

| 字段 | 覆盖 |
|---|---|
| section_path | **100%**（654/654） |
| title | **100%** |
| bbox | **100%** |
| embedding_text_hash | **100%** |
| headers_json（TABLE） | 401（全部表格 Child） |
| caption | 85 |
| unit | 77 |

一个 3 token 的「不适用」如果带着完整 section_path，经 embedding_text 拼接后仍可检索；
反过来，300 token 但没有章节路径的片段才是真废物。

## 5. 数据链路

```
COS: normalized.json (2.5 MB)
  ↓ NormalizedDocumentLoader（Jackson 3）
DocumentModel (1220 blocks / 345 tables)
  ↓ ParentChunker（按截断到 PARENT_DEPTH=2 的 section_path 归组）
104 个 Parent
  ↓ ChildChunker（TEXT/LIST 按句子累积；TABLE 按渲染 token 预算切行组）
654 个 Child
  ↓ EmbeddingService（百炼 text-embedding-v4，批量 ≤10）
654 个 1024 维向量
  ↓ ChunkPersister（行锁 → 写 → 校验 → 原子切换，单事务）
document_chunk（v2: 758 行 ACTIVE；v1: 758 行 SUPERSEDED 保留供审计）
```

## 6. 与预期的偏差

| # | 预期 | 实测 | 处置 |
|---|---|---|---|
| 1 | Parent 约 1500~3000 token | 中位 263（按最深路径时仅 48） | PARENT_DEPTH=2 已改善；进一步可降到 1（天花板 95.9%） |
| 2 | Child 100% 落在 300~700 | 仅 16.9%（最深路径）/ 现在 p50=263 | **口径已改为「≤700 硬上限 + 上下文完整性」** |
| 3 | 跨页表格逻辑合并 | 未合并 | 登记未决 |
| 4 | REEMBED / RETRIEVAL_ONLY / FULL_REPARSE | 显式抛异常 | 后移阶段 4 |

## 7. 未决问题（留给阶段 4/6）

1. **跨页表格未合并**：会以 page_start != page_end 的分片形式存在。
2. **5 个超大表格行**：是否要为它们单独做「按列拆 + 重复行标签」？先看阶段 6 的召回影响。
3. **caption 覆盖率仅 85/401**：没有题注的表格在 embedding_text 里缺表名。
4. **Parent 是否值得建向量**：§8.6 说评测证明有价值再补。
5. **PARENT_DEPTH 该取多少**：默认 2（104 个 Parent）。若上下文扩展不够，改一个常量即可。

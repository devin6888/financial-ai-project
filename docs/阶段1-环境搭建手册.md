## 3. 执行步骤

所有命令都在项目根目录 `D:\Project\myproject\financial-ai-project` 下执行。

### Step 0：确认基础镜像已就绪（你的加速器有坑）

你的 Docker 配置了加速器 `docker.m.daocloud.io`。它对 `library/*`（如 `hello-world`）正常，但对 `pgvector/pgvector` 命名空间返回 **401 Unauthorized**，会让构建在 `FROM pgvector/pgvector:pg16` 处直接失败。

办法是从可用的镜像源手动拉取，再改回原标签（这样 Dockerfile 一行都不用改）：

```powershell
docker pull docker.1ms.run/pgvector/pgvector:pg16
docker tag docker.1ms.run/pgvector/pgvector:pg16 pgvector/pgvector:pg16
docker images pgvector/pgvector
```

期望：能看到 `pgvector/pgvector:pg16`（约 631 MB）。

> 已在本机执行完成。**换了机器、或删除了该镜像后需要重做这一步。**

### Step 1：预检 SCWS 源码（本阶段唯一的**外部不确定性**）

zhparser 依赖 SCWS 分词库，需要从 GitHub 取源码编译。**先确认能拿到，再构建镜像**，避免构建到一半失败。

```powershell
curl.exe -sIL -o NUL -w "%{http_code}\n" https://github.com/hightman/scws/archive/refs/tags/1.2.3.tar.gz
```

期望输出：`200`

**注意**：hightman/scws 的真实 tag 是 `1.2.3`（**没有 `v` 前缀**）——GitHub 上不存在 `v1.2.3` 这个 tag，实测返回 404。如果仍 404，查一下真实 tag：

```powershell
git ls-remote --tags https://github.com/hightman/scws.git
```

查到后把 `docker/postgres/Dockerfile` 里的 SCWS 下载地址替换掉。

> 备选方案：改用上游发行包 `https://www.xunsearch.com/scws/down/scws-1.2.3.tar.bz2`，同时把 Dockerfile 里的 `tar -xzf` 改成 `tar -xjf`。
> Dockerfile 里已有 `[ -f configure ] || autoreconf -fi` 兜底，所以源码归档只含 `configure.ac` 也能编译。

### Step 2：构建镜像

```powershell
docker compose build postgres
```

期望：结尾出现 `naming to docker.io/library/finagent-postgres:16`，无 error。
**首次约 3~8 分钟**（要编译 SCWS 和 zhparser，这是本阶段最慢的一步）。

### Step 3：验证扩展确实进了镜像

```powershell
docker run --rm finagent-postgres:16 ls /usr/share/postgresql/16/extension/
```

期望：输出里能看到 `zhparser.control`、`zhparser--2.4.sql`、`vector.control`、`vector--*.sql`。
**看不到 zhparser 就说明编译没成功，不要往下走。**

### Step 4：启动容器

```powershell
docker compose up -d
Start-Sleep -Seconds 10
docker compose ps
```

期望：`finagent-postgres` 一行，STATUS 为 `Up ... (healthy)`。

这一步**只启动了数据库，还没有任何业务表** —— 表由应用启动时的 **Flyway** 创建。

> 阶段 1 的做法是用 `docker-entrypoint-initdb.d` 脚本，**已废弃**（见 §4.2）。要看到表，得先启动应用：`mvn spring-boot:run`。

### Step 5：确认表建好了

```powershell
docker compose exec postgres psql -U finagent -d finagent -c "\dt"
```

期望：列出 4 张表 `company`、`document`、`document_chunk`、`financial_fact`。

### Step 6：跑断言脚本（阶段 1 的正式验收）

用 Git Bash 执行：

```powershell
& "D:\Program Files\Git\bin\bash.exe" scripts/verify-db.sh
```

期望输出：

```
PASS  pgvector 扩展已安装
PASS  zhparser 扩展已安装
PASS  中文分词配置 chinese_zh 存在
PASS  中文分词真的切开了词（zhparser 优于 simple）
种子数据: company_id=1 document_id=1
PASS  1024 维向量可写入
PASS  向量相似度可计算
---- 全部通过 ----
```

**看到 `---- 全部通过 ----` 且退出码为 0，阶段 1 的数据层就算验收通过。**

> 不想用 bash？见 §4.3 的手动核对 SQL，效果等价。

### Step 7（可选）：固化版本

「一键重建」只有在版本被固定时才成立。记录两个值回写进 Dockerfile：

```powershell
docker image inspect pgvector/pgvector:pg16 --format "{{index .RepoDigests 0}}"
docker run --rm finagent-postgres:16 cat /zhparser-commit.txt
```

第一条输出 `pgvector/pgvector@sha256:...`，第二条输出一个 40 位 commit SHA。

把 Dockerfile 的 `FROM pgvector/pgvector:pg16` 改成 `FROM pgvector/pgvector@sha256:...`，
把 `ARG ZHPARSER_REF=master` 改成第二条输出的 SHA，然后重跑 Step 2 和 Step 3 确认仍能构建。

## 4. SQL 脚本说明

### 4.1 它们做了什么

| 脚本 | 内容 |
|---|---|
| `01-extensions.sql` | `CREATE EXTENSION vector`（向量）；`CREATE EXTENSION zhparser`（中文分词）；创建文本搜索配置 `chinese_zh`，把 n/v/a/i/e/l/j 七类词性映射到 simple 词典 |
| `02-schema.sql` | 建 4 张表：`company`、`document`、`document_chunk`、`financial_fact`；建 3 类索引：普通索引、GIN 全文索引、**HNSW 向量索引**；给 `document_chunk` 加一个自动生成的 `content_tsv` 列 |

### 4.2 schema 的管理方式（阶段 2 起已变更）

**不再使用 Docker init 脚本。**

| 机制 | 状态 |
|---|---|
| `docker/postgres/init/*.sql` + `docker-entrypoint-initdb.d` | ❌ **已删除** |
| `src/main/resources/db/migration/V*.sql` + Flyway | ✅ 当前方式 |
| `docker compose down -v` | ⚠️ 只在需要**彻底重置**时用；**改表不需要** |

**改表只需新增一个迁移文件**（例如 `V3__add_xxx.sql`），然后启动应用：

```powershell
mvn spring-boot:run      # Flyway 在启动时执行未应用的迁移
```

查看迁移历史：

```powershell
docker compose exec -T postgres psql -U finagent -d finagent -c "select version, description, success from flyway_schema_history order by installed_rank;"
```

> **为什么改掉**：init 脚本只在数据卷为空时执行一次，意味着**每改一次表就要 `down -v` 丢掉全部数据**。
> 阶段 3~10 会反复改 schema，那样不可持续。引入 Flyway 后，**改表只需加文件**。

### 4.3 手动核对

**手动核对**（不用 bash**手动核对**（不用 bash，逐条粘进 psql）：

```powershell
docker compose exec postgres psql -U finagent -d finagent
```

进去以后依次执行：

```sql
-- 1) 两个扩展是否都装了？期望两行：vector / zhparser
SELECT extname FROM pg_extension WHERE extname IN ('vector','zhparser');

-- 2) 中文分词配置是否存在？期望一行：chinese_zh
SELECT cfgname FROM pg_ts_config WHERE cfgname='chinese_zh';

-- 3) 【最关键】中文到底切没切开？期望输出多个词，如 '2025':4 '营业收入':6 '贵州':1 '茅台':2 ...
SELECT to_tsvector('chinese_zh','贵州茅台2025年营业收入同比增长');

-- 对照：内置 simple 分词器只会输出 1 个整体 token
SELECT to_tsvector('simple','贵州茅台2025年营业收入同比增长');

-- 4) 表是否建好？期望 4 行
SELECT tablename FROM pg_tables WHERE schemaname='public' ORDER BY tablename;

-- 5) 向量索引是否建好？期望包含 idx_chunk_embedding
SELECT indexname FROM pg_indexes WHERE tablename='document_chunk';

\q
```

## 5. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| Step 2 下载 SCWS 报 404 | tag 名不对 | 回到 Step 1，换 tag 或改用 xunsearch 发行包 |
| 构建报 `configure: not found` | 归档里只有 `configure.ac` | Dockerfile 已有 `autoreconf -fi` 兜底；若仍失败，确认 `autoconf automake libtool` 已装 |
| 构建报 `pg_config: not found` | PG 开发包没装好 | 确认 `postgresql-server-dev-16` 在 apt 列表里 |
| Step 3 看不到 `zhparser.control` | zhparser 编译失败 | 重跑构建，看 `make` 阶段的报错 |
| `docker compose up` 报端口占用 | 5432 被别的 PG 占用 | 改 `docker-compose.yml` 端口映射为 `"15432:5432"`，并同步改本文档里的 psql 连接方式 |
| `\dt` 看不到表 | **应用还没启动过**（表由 Flyway 建） | 启动应用：`mvn spring-boot:run`；仍不行就看 `flyway_schema_history` |
| 报 `text search configuration "chinese_zh" does not exist` | `01-extensions.sql` 没执行成功 | 按 §4.3 手动执行 |
| 中文输出乱码 | PowerShell 控制台编码 | 先执行 `chcp 65001`，或把输出重定向到文件再看 |
| 容器一直 `unhealthy` | 初始化还没完成 | 等 10~20 秒；仍不行则 `docker compose logs postgres` |

## 7. 清理与重建

```powershell
# 停止容器，保留数据
docker compose down

# 停止并删除数据（彻底重置；下次**启动应用**时 Flyway 会重建全部表）
docker compose down -v

# 删除镜像（要重新编译时用）
docker rmi finagent-postgres:16
```
